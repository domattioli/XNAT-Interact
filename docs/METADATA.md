# Metadata Reference — XNAT-Interact

What every metadata parameter means, where it comes from, and **how the ingest pipeline handles
it** — with emphasis on the **UIDs**, because they are the backbone of identity and duplicate
detection. Companion to [`DATA_MODEL.md`](DATA_MODEL.md) (the why) and
[`XNAT_MODEL.md`](XNAT_MODEL.md) (the pyxnat surface).

> **Legend for "Pipeline handling":**
> `read` = used but not modified · `clobber` = overwritten with a standardized value ·
> `stash` = original copied to a private tag before change · `derive` = computed by the tool.
> ⚠ marks behavior that is a **known defect** (tracked in #33) or **scheduled to change** per
> the `DATA_MODEL` identity/dedup spec.

---

## 1. DICOM UIDs — the identity backbone

UIDs are globally-unique DICOM identifiers. Three levels nest: **Study** (one imaging study /
OR case) → **Series** (one acquisition run within it) → **SOP Instance** (one image/frame).

| UID | DICOM tag | Native meaning | Current pipeline handling | Intended (per DATA_MODEL) |
|---|---|---|---|---|
| `StudyInstanceUID` | `(0020,000D)` | Identifies the **whole study / OR case** | ⚠ **clobber** → set to `intake_form.uid`; original stashed in `Old_StudyInstanceUID` | **preserve original** as a *corroborating* case-dedup signal (not authority — UIDs can be regenerated by re-export) |
| `SeriesInstanceUID` | `(0020,000E)` | Identifies an **acquisition run** within the study | ⚠ **clobber** → `intake_form.uid` (run boundaries lost); original stashed in `Old_SeriesInstanceUID` | **preserve original** as metadata so per-run structure is reconstructible later (runs not modeled, but not destroyed) |
| `SOPInstanceUID` | `(0008,0018)` | Identifies a **single image/frame**; MUST be unique per instance | ⚠⚠ **clobber** → `intake_form.uid` for *every* frame → all frames share one UID (**H1 defect**, violates per-instance uniqueness; corrupts frame ordering) | **unique per instance**; original stashed as a *corroborating* image-dedup signal |

**Why this matters:** per-instance `SOPInstanceUID` uniqueness underpins **frame order** (a skill
metric) and **image identity** (ML leakage avoidance). Collapsing them (H1) breaks both. Because
re-export/anonymizers can regenerate UIDs, the **authoritative** dedup keys are *content* hashes
(below); the original UIDs are **corroborating evidence** that raise confidence when they agree.

**Storage note:** when UIDs are used as XNAT labels, dots are replaced with underscores
(`1.2.3` → `1_2_3`), because that is how XNAT stores label strings.

## 2. Other DICOM tags the pipeline reads or rewrites

| Tag | DICOM | Meaning | Handling |
|---|---|---|---|
| `InstanceNumber` | `(0020,0013)` | Frame order within the run | `read` → drives filename + ordering; falls back to row index if absent (#30 guard) |
| `ContentTime` | `(0008,0033)` | Acquisition time of the frame | `read` → captured in `TIMEINFO` |
| `StudyDate` | `(0008,0020)` | Date of the study (**PHI / date-of-service**) | `clobber` → `intake_form.operation_date`; original ⚠ stashed in `Old_StudyDate` (re-id leak — should be hashed for dedup then stripped) |
| `StudyTime` | `(0008,0030)` | Time of the study | `clobber` → `intake_form.epic_start_time`; original stashed in `Old_StudyTime` |
| `NumberOfStudyRelatedInstances` | `(0020,1208)` | Count of instances in the study | `clobber` → `num_valid_shots`; original stashed in `Old_NumberOfStudyRelatedInstances` |
| `Manufacturer` / `ManufacturerModelName` | `(0008,0070)` / `(0008,1090)` | C-arm device identity | `read` → drives the **device-profile pixel-redaction mask** (DATA_MODEL §4.2) + case-dedup corroboration |
| `BurnedInAnnotation` | `(0028,0301)` | Flags burned-in pixel PHI | `read` → gates pixel de-id |
| `PatientName` / `PatientID` | `(0010,0010)` / `(0010,0020)` | Patient identity (**PHI**) | de-identified (PN-VR redaction); **patient identity destroyed**, never pseudonymized |

## 3. XNAT-Interact private-tag block `(0x0019, ....)`

The tool writes its provenance + de-id audit trail into a private group. The original values are
captured here **before** standardization (this is the provenance the audit/dedup logic relies on).

| Tag | VR | Contents |
|---|---|---|
| `(0x0019,0x1000)` | LT | Derived-metadata items (`key: value`) ⚠ written in a loop to one address — collision risk, like the H2 defect |
| `(0x0019,0x1001)` | LT | `Old_StudyDate: <original>` ⚠ re-id leak — strip after hashing for dedup |
| `(0x0019,0x1002)` | LT | `Old_StudyTime: <original>` |
| `(0x0019,0x1003)` | LT | `Old_StudyInstanceUID: <original>` — corroborating case key |
| `(0x0019,0x1004)` | LT | `Old_SeriesInstanceUID: <original>` — run boundary metadata |
| `(0x0019,0x1005)` | LT | `Old_SOPInstanceUID: <original>` — corroborating image key |
| `(0x0019,0x1006)` | IS | `Old_NumberOfStudyRelatedInstances: <original>` |
| `(0x0019,0x1007)` | LT | Within-case **duplicate flag** (`IS_QUESTIONABLE`) — informational note; the shot is **kept** |
| `(0x0019,0x1008)` | LT | Provenance: "Metadata de-identified & standardized by XNAT-Interact on `<datetime>`" |

## 4. Tool-derived metadata (`_derived_metadata`)

Computed by the pipeline and written into the private block:

| Key | Meaning |
|---|---|
| `ACQUISITION_SITE` | Imaging site / institution context |
| `DATETIME` | Standardized US-Central processing timestamp |
| `TIMEINFO` | Captured `ContentTime` / `SeriesTime` / `StudyTime` (acquisition timing) |
| `UID_INFO` | All original UIDs captured (dots → underscores) — the belt-and-suspenders copy of the native identity |

---

## 5. Intake-form parameters (`running_text_file`)

Supplied by the uploader; these set the standardized identity + case attributes.

| Field | Role |
|---|---|
| `SUBJECT_UID` | Becomes `intake_form.uid` — the case/subject key the pipeline currently writes into the UIDs ⚠ (see §1 / H1) |
| `ASSESSOR_UID` | Identifier for the person performing the upload/assessment |
| `FILER_HAWKID` | Uploader HawkID ⚠ surgeon identity should become a keyed pseudonym (DATA_MODEL §3.2) |
| `OPERATION_DATE` | Surgery date → written to `StudyDate` (**date-of-service; hash for dedup, don't store readable**) |
| `SURGICAL_PROCEDURE_INFO` | Procedure type (ARTHRO / TRAUMA) + name (e.g. `1A_KNEE_ARTHROSCOPY`) |
| `SKILLS_ASSESSMENT_INFO` | Skill-assessment context (the primary research use) |
| `SCAN_QUALITY` | Usability flag |
| `STORAGE_DEVICE_INFO` | Source device provenance |

## 6. How identity composes (quick map)

| Concern | Authoritative key | Corroborating | Source |
|---|---|---|---|
| Image | `sha256(raw PixelData)` | `Old_SOPInstanceUID` | pixel data + §1/§3 |
| Case | set of image content-hashes | `Old_StudyInstanceUID`, `HMAC(salt, StudyDate+StudyTime+Manufacturer)` | §1/§2 |
| Surgeon | `HMAC(salt, HawkID)` pseudonym | — | `FILER_HAWKID` (§5) |
| Patient | — destroyed — | — | §2 |

See `DATA_MODEL.md` §3–§5 for the full identity / de-id / dedup model and the deferred fixes
(H1 SOPInstanceUID, StudyInstanceUID handling, `Old_StudyDate` strip).
